## 2. What was found and fixed (this pass)

### P1 — exact correctness

1. **Hostile `.unbc` drove a panic in the register-VM.** `Program::validate`
   never bounded `source_map` spans vs the embedded source text; when the VM
   pushed a call frame the display path sliced outside the source and panicked
   (`src/source.rs:42`). Repro: flip bytes 637/633/636/648/651/663/666/669 by
   XOR 0x20 — all abort the worker thread with `range … out of bounds`.
   **Fix**: bounds check in `Program::validate` (spans checked against the
   embedded source char count; `Source::span` is now total — clamps instead of
   slicing). A 380-offset fuzz of the same file now yields 0 crashes; every
   failure is a clean `malformed bytecode` exit.
2. **Crafted `.unbc` reserved ~66 GB (`Op::ArgBegin` operand).** VM did
   `Vec::with_capacity(ins.d as usize)` twice unchecked; verifier had no arm for
   `ArgBegin`. **Fix**: verifier rejects `d > 256` (plus `MakeClass`
   field-name slots and `BuildTupleNamed` bounds — same class).
3. **List-handle Int aliasing in the Int JIT (silent miscompilation).**
   User Ints ≥ 2^62 alias `IntVec` arena handles. Two paths were affected:
   `xs.add(n)` misread the value as a row handle (KIND_OUTER promotion), and
   `-> xs` identity returned a raw handle mis-tagged `TAG_INTLIST` (wrong type
   out of the ABI boundary). `int_dict_seen` also lumped IntVec handles in with
   dict/instance handles, so the row-insert intrinsic refused to lower.
   **Fix**: hidden `param_tags` ABI bit per passed handle; a per-proto
   `unsafe_param_mask(code)` entry guard bails list-typed arguments into any
   frame that consumes a parameter as an Int (arithmetic/compare/display);
   the Return probe now only fires for union call results or raw parameter
   registers; IntVec row insert uses a foreign-handle predicate (dict/instance/
   method/iter), never the list marker; `IntVec` push/set gained
   `un_list_int_push_scalar`/`un_list_int_set_scalar` for plain Ints.
   `functions.un` pinned the identity case (was returning length 1 for
   `[7,8,9]`); `functions.un` identity list round-trips restored.
4. **`dict` double-borrow panic + silent data loss on re-entrant `__eq__`.**
   `dict_set_item` held `RefCell::borrow_mut` across `key_eq` → user `__eq__`
   → nested dict access → `RefCell already borrowed` (caught by the step
   shield, so execution continued **with the write silently lost**, plus a
   duplicate entry minted). Same class in `dict_get`/`set_get`/`dict.get`.
   **Fix**: snapshot/candidate/generation-retry pattern (`find_index`)
   everywhere `key_eq` may run — no user code ever executes under a map
   borrow. Threads that re-enter now either observe a consistent map or retry
   the operation; the write cannot vanish.
5. **Compound-assign desugar emitted poisoned source spans into `.unbc`.**
   `span.1` (a *length*) was treated as an *end*: `span.1 - start` wrapped
   `2907 - 2910` into a usize underflow. The round-trip runner never saw it
   because `.unbc` output with poisoned spans was accepted unconditionally
   (and, once accepted, produced the panic of finding 1).
   **Fix**: `span.1` used directly; the verifier spans check (finding 1)
   rejects the class permanently. Note: the desugar itself produced corrupt
   spans for *any* source position beyond the first few hundred bytes.

### P2 — correctness / resilience (all are run-time catchable today, or were silent)

6. **Typed compound assignment** (`x: int += 1`) — `Binary(Typed(..))` was
   unsupported below the parser; in a function the bytecode failed
   `transfer::analyze` (stack depth -1); at module level a runtime
   "unsupported node kind Typed". **Fix**: desugar unwraps the annotation
   (load side) and re-wraps the store target; works at both levels now.
   Tests added (`test/unit/runtime/compound_assign.un`).
7. **Multiple `catch` clauses silently dropped.** The compiler kept only the
   first; the rest were unreachable. **Fix**: compile error
   (`multiple 'catch' clauses are not supported`); negative manifest pins it
   (`multi_catch.un`). **Decision recorded as D-083.**
8. **`use a.*`** was parsed as a path (`a.*`) and panicked
   ("module ...\\a\\* not found"). **Fix**: maps to the wildcard import
   (`use a { * }`). **D-081.**
9. **`enum E { A = -1 }`** → `internal: invalid enum value` (unary
   consts were never constant-folded). **Fix**: fold `+/-/~` unary chains and
   `Typed` wraps; non-integer member values error as
   `enum member 'X' must be an integer literal`. Tests added (`enum.un`).
10. **math boundary honesty**: `math.pow(2, 63)` saturated to Int (free
    pinning test passed vacuously against the lossy Int→Float boundary
    comparison); `math.abs(i64::MIN)` returned i64::MAX; `math.gcd(MIN, …)`
    could go negative; `gcd`/`lcm` now agree on `unsigned_abs`. The pinning
    test (`math.un`) now also pins `type(math.pow(2, 63)) == float.`
11. **HTTP `head()`** always errored against a conformant server (the strict
    `Content-Length` equality didn't special-case HEAD's would-be body); now
    1xx/204/304/HEAD are exempt.
12. **WS receive delivered control frames as messages** (PING→pong ok, but
    PONG and anything else flowed through to the app), binary frames silently
    produced `""`, and unlimited ping floods were possible. **Fix**: PONG
    skipped, binary/reserved opcodes produce catchable errors, control-frame
    flood cap (1000), invalid-UTF-8 text frames error out. Error messages
    unified (`wss://` no-longer claims support).
13. **fs timestamps pre-1970** clamped silently to the epoch; negative tick
    arithmetic instead.
14. **`use` / `MakeFunc` / `MakeClass` 16-bit truncation bounds**: compile
    errors at the boundaries (call-site name tables > 65535, class fields >
    255, default params > 255, use imports > 255) — previously silent aliasing.
15. **Compound-assign span poison (see 5)**.

## 3. Known residuals (not defects this pass accepted)

- **Outer-IntVec rows compared as raw handles** (`xs[0] < 1` on a nested list):
  elements of KIND_OUTER parents are arena row handles carried as unmarked
  i64s. The JIT does not distinguish them from Ints; the interpreter type-errors
  there. Same class as finding 3, narrower trigger; the Int-JIT's contract is
  "Int semantics", and nested-list comparisons are outside it. Not silent in
  the VM (UV_JIT=0), and differential entries exercise it.
- **`use re { * }` vs `use re.*`**: both forms now do the wildcard at the
  import layer; the direct `use re.*` does **not** enforce a per-file order.
- **List-valued fast-path elements ≥ 2^62**: the interpreter treats them as
  Ints fine (compare is exact); the JIT sees identical values and miscompares
  only if they reach a comparison arm *and* alias a live arena slot. Guarded
  by the `param_tags` entry guard only for FFI arguments, not element reads.
  This is the same documented IntVec-handle ambiguity class.
- **Nested JIT-only IntList call with zero Int-consuming ops in the callee**:
  would pass the entry guard regardless of (1); by construction those frames
  have no capacity to miscompile a handle.
- **`iter.range(1, len(xs))`-style nested JIT call as a range argument**:
  remains outside the Int-JIT (documented as fallback).
